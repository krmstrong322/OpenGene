# OpenGene Backend

Deterministic plasmid-editing engine and REST API — the non-AI core (Phase 1)
of the OpenBioMap / OpenGene specification.

All biological sequence manipulation happens here, in validated Python. Per the
**Sequence Invariant**, every mutation is routed through
`opengene.core.sequence`, which validates via Biopython before returning; no
free-form sequence string from outside the engine can mutate state.

## Stack

- **FastAPI** — REST API
- **Biopython** — parsing, restriction catalog (REBASE/NEB), translation
- **primer3-py** — Tm, hairpin/dimer analysis, primer design
- **Pydantic v2** — validated data models (`PlasmidRecord`, `Feature`, `Primer`)

## Install & run

```bash
cd backend
python -m venv .venv && . .venv/bin/activate
pip install -e ".[dev]"

# run the API
uvicorn opengene.api:app --reload --port 8000

# run the tests
pytest -q
```

OpenAPI docs are served at `http://localhost:8000/docs`.

## What it does

| Area | Capability |
|------|-----------|
| **File I/O** | Import GenBank, FASTA, EMBL, SnapGene `.dna`; export GenBank/FASTA/EMBL. `.dna` is import-only (no writer in Biopython — export to GenBank to round-trip). |
| **Editing** | Insert, delete, mutate, replace-range, reverse-complement. Feature coordinates shift correctly; circular origin wrap-around is handled. |
| **ORFs** | Detection across all 6 reading frames, including ORFs that cross the origin of circular records. |
| **Restriction** | Cut-site mapping, digest fragment sizes, unique-cutter detection using every commercially available enzyme (NEB included; not yet filterable to NEB only). |
| **Primers** | Tm / GC / hairpin / dimer analysis and PCR primer-pair design around a target region. |
| **Annotation** | Pure-Python **seed-and-extend** auto-annotation against a bundled 33-part library (promoters, terminators, tags, protease sites, resistance genes, fluorescent proteins, and replication origins — ColE1/pUC, f1, SV40, p15A) on both strands, wrapping the origin. Local alignment tolerates substitutions **and** indels, finds **partial** parts, and reports each hit's **identity** and **coverage** (thresholds `min_identity` / `min_coverage`, default 0.80). A ribosome-binding site is only called upstream of a start codon; a short motif inside a longer CDS hit is dropped. `/health` reports whether BLAST+ is installed; annotation doesn't require it. |

## Feature library

`opengene/data/feature_library.json` is generated by
`scripts/build_feature_library.py`, which combines canonical regulatory /
tag motifs with gene sequences extracted from public NCBI reference
plasmid records (pBR322, pUC19, pEGFP-N1, pACYC184, mCherry). Regenerate with:

```bash
python scripts/build_feature_library.py /path/to/reference/*.gb
```

## API surface

```
GET    /health
POST   /records                      create from raw sequence
GET    /records                      saved records, newest first (summaries, no sequence)
GET    /records/{id}                 fetch
DELETE /records/{id}                 remove
POST   /records/import               upload a .gb/.fasta/.embl/.dna file
GET    /records/{id}/export?fmt=     export (genbank|fasta|embl)

POST   /records/{id}/insert          {position, sequence}
POST   /records/{id}/delete          {start, end}   (start>end wraps origin)
POST   /records/{id}/mutate          {position, base}
POST   /records/{id}/replace         {start, end, sequence}
POST   /records/{id}/reverse_complement

GET    /records/{id}/orfs?min_aa=
GET    /records/{id}/cut_sites?enzymes=EcoRI,HindIII
POST   /records/{id}/digest          {enzymes: [...]}
GET    /records/{id}/unique_cutters

POST   /primers/analyze              {sequence, target_tm}
POST   /records/{id}/design_primers  {region_start, region_end, target_tm}

POST   /records/{id}/annotate        {replace_existing, min_identity, min_coverage}
POST   /records/{id}/features        add a manual feature
DELETE /records/{id}/features/{fid}
GET    /feature_library
```

Coordinates are **0-indexed, half-open `[start, end)`**. A circular feature may
wrap the origin, in which case `start > end`.

## Scope notes

- Phase 2 (AI intent parsing / function-calling layer) is intentionally not in
  this core. The API is the tool surface those agents will call.
- Auto-annotation is pure-Python by design; BLAST+ is an optional accelerator,
  never a hard dependency.
